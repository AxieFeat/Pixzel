# Сборка демо Cristalix

Экран собирается из стандартных `Button`, `Text`, `TextField`, `Image`, `Surface` и `ScrollView` Pixzel. В демо нет наследников `Element` / `AbstractElement`, собственных реализаций кнопок или раскладки по строковым `id`.

## Подключение

После создания `Ui` и загрузки шрифтов (готовый запуск — в `CristalixDemo.kt`):

```kotlin
val data = MenuData.load()
val model = MenuModel(data = data)
val art = MenuArt.load(context, resources, data)
val menu = CristalixMenu(
    ui, model, art,
    style = NavigatorStyle(catalogue = CatalogueStyle(maximumColumns = 6)),
    actions = MenuActions { game -> println("Выбран режим: ${game.id}") }
)
ui.root.add(menu.root)
```

`CristalixMenu` — координатор собранного дерева. Его `root` — обычный `Surface`. Классы `ToolbarView`, `CatalogueView`, `ComposerView` и другие хранят ссылки на стандартные элементы и состояние; они не создают новые типы элементов Pixzel. Ресурсы изображений принадлежат переданному `ResourceScope`, дерево и его подписки закрывает `Ui`.

## Изменение содержимого

Данные находятся в `pixzel-demo/src/main/resources/cristalix/data/`:

| Файл | Что менять |
| --- | --- |
| `games.tsv` | Игры, названия, иконки, цвета, онлайн, категории, языки, теги и рейтинги |
| `banners.tsv` | Любое количество баннеров, подписи, действия и длительность показа |
| `reviews.tsv` | Отзывы, оценку, размеры и число колонок, занимаемых плиткой |
| `languages.tsv` | Доступные языки и их порядок в списке |
| `metrics.tsv` | Общие счётчики из видеореференса |

Формат — UTF-8, столбцы разделены табуляцией. Порядок столбцов определяется заголовком. Внутри значения `\n` обозначает перенос строки, `\t` — табуляцию, `\\` — обратную косую черту. Списки тегов и языков разделяются `|`. Имена `icon` / `image` соответствуют PNG в `cristalix/reference/`. Категории и языки выпадающих списков берутся из данных.

Вместо файлов можно передать свой `MenuData`:

```kotlin
val defaults = MenuData.load()
val data = defaults.copy(games = defaults.games + GameMode(
    id = "new-game",
    name = "Новая игра",
    online = 42,
    color = 0x35426D,
    icon = "sword",
    category = "Своя категория",
    description = "Описание нового режима",
    tags = listOf("PVP", "КОМАНДЫ"),
    languages = setOf("RU")
))
```

Для новой игры не нужно писать класс плитки, добавлять ветку `when` в раскладку или менять обработчики поиска. `MenuArt` тоже передаётся извне: можно использовать собственные `ImageHandle`, без загрузчика Arc.

## Где находится поведение

| Задача | Файл |
| --- | --- |
| Сборка экрана и координация окон | `CristalixMenu.kt` |
| Поиск, категории, языки и избранное | `MenuModel.kt` |
| Плитки, прокрутка, анимация фильтрации | `CatalogueView.kt`, `GameCardPosition.kt` |
| Панель инструментов, карусель и общий список выбора | `NavigatorView.kt` |
| Отзывы, навигация, шаблоны плиток и форма | `ReviewsView.kt`, `ReviewNavigation.kt`, `ReviewTiles.kt`, `ComposerView.kt` |
| Общие стили кнопок, сборка, размещение и фокус окон | `PixelUi.kt` |
| Пиксельные рамки и рисование декора | `PixelDrawing.kt` |
| Раскладка произвольных плиток и прокрутка | `TileSize.kt`, `TileBoard.kt` |

Стиль задаётся данными: `PixelButtonStyle.copy(...)`, `NavigatorStyle` и `CatalogueStyle`. Скин использует настоящую кнопку Pixzel: нажатия, захват мыши, фокус, клавиатура и доступные действия остаются штатными.

Размещение связывается с самими элементами:

```kotlin
val panel = ui.compose("example") {
    val title = text("Заголовок")
    val button = action("open", "Открыть", PixelButtonStyle.PURPLE) { /* действие */ }
    parent.arrange {
        place(title) { Rect(12f, 12f, it.width - 24f, 28f) }
        place(button) { Rect(12f, 52f, 160f, 38f) }
    }
}
```

`id` служит для диагностики и проверок, а не выбирает логику раскладки. Неразмещённый явно дочерний элемент заполняет контейнер. Отзывы используют общий алгоритм masonry: `span`, `height`, `expandedHeight` описывают раскладку в данных, без проверок конкретного класса или номера отзыва.

Многострочный ввод — отдельный `MultilineEditor`, собранный на обычном `Surface`: в текущем стандартном `TextField` нет многострочного режима. Этот контроллер отвечает только за редактирование, выделение, Unicode, буфер обмена и историю; форма и её оформление находятся отдельно.

Сохранена прежняя анимация поиска: тот же `GameCardPosition`, пружины, последовательное появление и исчезновение плиток. Смещение общей прокрутки применяется после анимированной позиции, поэтому баннер и каталог движутся вместе. Невидимые плитки не рисуются; прокрутка меняет смещение, без пересоздания элементов.

## Проверка

```powershell
.\gradlew.bat :pixzel-demo:test :pixzel-demo:detekt verifyBoundaries verifyCodeStyle
.\gradlew.bat :pixzel-demo:cristalix --args="--smoke --verify --width=2560 --height=1440"
```

Тест `MenuCompositionTest` собирает экран с вымышленными играми и изображениями, проверяет стандартные типы всех элементов, поиск, избранное, действие запуска и закрытие окон. Отдельные тесты проверяют карусель с произвольным количеством баннеров, раскладку плиток, редактор, модель, сохранение избранного и прежнюю анимацию поиска. Нативная проверка выполняет 1050 кадров с настоящими событиями окна и сохраняет 12 снимков.
